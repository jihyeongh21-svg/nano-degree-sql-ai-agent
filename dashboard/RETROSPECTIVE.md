## 강의에서 얻은 것

**1. 대시보드는 독자에서 시작한다.**
처음에는 "데이터로 멋진 차트를 만든다"고 생각했다. 강의에서 "누가, 언제, 무엇을 결정하려고 보는가"를 먼저 정하니 KPI와 차트가 저절로 좁혀졌다. 병원 경영기획팀장이 월초 회의 전날 본다고 정하자, 수십 개 컬럼 중 필요한 숫자는 명세서 수, 진료비, 수진자 수 세 개였다.

**2. AI Agent는 작게 나눠 시키고, 숫자는 내가 검증한다.**
Claude Code에 데이터 준비 → 집계 → KPI → 차트 → 인사이트 순서로 한 단계씩 맡겼다. 한 번에 하나씩 시키니 무엇이 바뀌었는지 확인하기 쉬웠다. 차트가 그려졌다고 숫자가 맞는 것은 아니어서, KPI와 종별 진료비를 SQL 수업에서 직접 낸 결과와 대조했다. 인사이트 문장도 "겨울 700~840건"이라고 썼다가 2024년 1월(532건)이 범위를 벗어나는 것을 보고 "대부분"으로 고쳤다.

**3. SQL 수업과 대시보드가 이어진다.**
종별 건당 진료비 차트는 SQL 실습 2의 `JOIN` + `GROUP BY` 쿼리와 같은 계산이다. `code_type = '종별코드'` 조건을 빠뜨리면 다른 코드가 섞인다는 것도 SQL에서 배운 그대로 적용됐다. SQL로 질문에 답하고, 대시보드로 그 답을 매달 보게 만드는 흐름을 이해했다.

**4. 정적 대시보드와 동적 대시보드의 차이.**
지금 대시보드는 CSV를 집계해 고정한 정적 페이지다. Supabase에 연결하면 테이블 값이 바뀔 때 화면도 바뀐다. 공개 저장소에는 anon key만 두고 데이터 보호는 RLS로 해야 한다는 점도 배웠다.

## 내 분야에 적용한다면

- **외래 수요 예측 화면**: 호흡기 질환 명세서가 겨울에 여름의 2배 이상이었다. 병원 운영 쪽이라면 월별 상병군 추이를 보고 겨울 외래 인력과 예산을 미리 잡는 대시보드로 쓸 수 있다.
- **만성질환 환자 관리**: 고혈압·당뇨 환자의 방문 간격(SQL 실습 3)을 대시보드에 붙이면, 90일 넘게 오지 않은 환자 목록을 매주 확인하는 화면이 된다.
- **반복 작업 스킬화**: 매달 데이터를 받아 집계하고 배포하는 과정을 `/동기화`, `/배포` 같은 클로드 스킬로 저장해 손을 줄이고 싶다.
