## 무엇을 만들었나

수업에서는 건강보험 청구 데이터로 병원 경영기획팀장용 대시보드를 따라 만들었고, 과제에서는 같은 방법을 내 관심사인 투자에 적용했다.
"원화로 미국 지수에 적립식 투자하는 사람이 매달 매수 전에 시장 분위기를 점검하는 화면"을 목표로 정하고,
S&P 500 그래프 1개에서 시작해 지표 카드, 시장 신호, 차트 4개, 적립식 시뮬레이터까지 단계별로 키웠다.

## 강의에서 얻은 것

**1. 대시보드는 독자에서 시작한다.**
처음에는 "데이터로 멋진 차트를 만든다"고 생각했다. 강의에서 "누가, 언제, 무엇을 결정하려고 보는가"를 먼저 정하니 KPI와 차트가 저절로 좁혀졌다. 수업 실습에서 병원 경영기획팀장을 독자로 정하자 필요한 숫자가 명세서 수, 진료비, 수진자 수 세 개로 줄었던 것처럼, 과제에서도 독자를 "매달 적립식으로 사는 개인"으로 정하자 수많은 시장 지표 중 추세, 과열, 공포, 고점 대비 위치, 금리차, 환율 여섯 개만 남았다. 특히 원화로 사는 사람이라는 조건 덕분에 환율을 신호에 넣고 시뮬레이터에도 환율 변화를 반영하게 됐다.

**2. 작게 만들고 키운다.**
처음부터 대시보드를 한 번에 만들지 않고 S&P 500 그래프 1개로 데이터 받기, 집계, 차트 틀을 먼저 확인했다. 그 틀이 잡히니 지표를 늘리고 차트를 붙이는 일은 같은 방식의 반복이었다. 막히는 곳이 생겨도 어느 단계에서 생겼는지 바로 알 수 있었다.

**3. AI Agent는 작게 나눠 시키고, 숫자와 문장은 내가 검증한다.**
Claude Code에 한 단계씩 맡기니 무엇이 바뀌었는지 확인하기 쉬웠다. 그래도 그대로 믿을 수는 없었다. S&P 500 그래프의 범례는 10년 +271.4%인데 위쪽 지표는 +264.2%로 서로 달랐고, 주간 데이터가 첫 거래일이 아닌 그 주 마지막 날부터 시작한 탓이었다. 금리 카드에 "연초 대비 +19.38%"처럼 금리를 변화율로 표시한 것은 %p로 바꿨고, 환율이 "달러 쌈"인데 설명이 "살 때 부담"으로 나온 문장도 화면을 직접 보고서야 찾았다. 수업 실습에서도 인사이트 문장의 "겨울 700~840건"이 2024년 1월(532건)과 맞지 않아 "대부분"으로 고쳤다. 차트가 그려졌다는 것과 숫자·문장이 맞다는 것은 다른 일이다.

**4. 데이터는 받을 수 있는 곳에서, 출처를 밝혀서.**
수업 실습에서는 로컬 MySQL 접속이 막혀 강의 백업 시트로 우회하고 행 수·합계로 같은 데이터인지 확인했다. 과제에서는 시세 사이트가 브라우저 검증 페이지로 막혀 FRED 공개 CSV로 바꿨다. 막혔을 때 다른 경로를 찾되, 출처와 기준일을 화면에 적어 두는 것이 중요했다.

**5. 규칙은 화면에 적는다.**
신호 배지(상승 추세, 과열, 공포 등)는 200일선, RSI 70/30, VIX 20/30 같은 단순 규칙으로 정했다. 규칙을 숨기면 신호를 맹신하게 되므로 각 카드에 기준을 그대로 적고, 맨 아래에 투자 권유가 아니라는 안내를 넣었다.

**6. 정적 대시보드와 동적 대시보드의 차이.**
지금 대시보드는 데이터를 받아 집계해 고정한 정적 페이지라, 최신 값을 보려면 스크립트를 다시 돌려야 한다. Supabase 같은 DB에 연결하면 값이 바뀔 때 화면도 바뀐다. 공개 저장소에는 anon key만 두고 데이터 보호는 RLS로 해야 한다는 점도 배웠다.

## 내 분야(백엔드 개발)에 적용한다면

- **정적 파일을 API로**: 지금은 파이썬 스크립트가 집계 결과를 `invest_data.js` 로 굳혀 두는 구조다. 백엔드라면 스케줄러가 매일 FRED 데이터를 받아 DB에 쌓고, `/signals`·`/cards` 같은 API가 집계 결과를 캐시해 내려주는 구조로 바꾸겠다. 화면은 그대로 두고 데이터 계층만 교체할 수 있게 응답 형식을 지금의 JSON 구조와 맞추면 된다.
- **운영 모니터링 대시보드**: "신호 + 기준값" 구조는 서비스 운영 지표에 그대로 쓸 수 있다. API 응답시간 p95, 에러율, DB 커넥션 사용률에 임계값을 두고 정상·주의·장애 배지로 보여 주면, 장애 대응 회의 전에 보는 화면이 된다. 이때도 독자(당직 개발자)와 보는 때(배포 직후, 알림 수신 시)를 먼저 정해야 지표가 좁혀진다.
- **SQL 수업 활용**: 윈도우 함수(`LAG`)로 구한 재방문 간격, CTE로 나눈 코호트 집계는 회원 리텐션이나 휴면 회원 탐지 쿼리와 같은 틀이라, 통계 API를 만들 때 바로 쓸 수 있다.
- **개발 업무에 Agent 적용**: 이번처럼 작게 나눠 요청하고 결과를 검증하는 방식으로 API 스펙 작성, 테스트 코드 생성, 마이그레이션 스크립트 같은 반복 작업을 Claude Code에 맡기고, 자주 쓰는 절차는 스킬로 저장하겠다.
