# 웹 대시보드 실습·과제 정리

오즈코딩스쿨 AI 헬스케어 3기 웹 대시보드 특강(2026-10-20 ~ 10-22, 3일) 내용을 정리했습니다.
SQL 특강에서 다룬 `kr_claims` 데이터를 Claude Code로 웹 대시보드로 만들고, GitHub Pages로 배포한 뒤 Supabase에 연결하는 흐름입니다.

> 데이터는 실제 환자 기록이 아닌 실습용 가상 데이터입니다. 숫자를 실제 통계로 해석하지 않습니다.

| 2일차 | 10-21(수) | `kr_claims` 로 대시보드 만들기 + GitHub Pages 배포 | `dashboard.html` (KPI + 차트) |

## 3. 1일차: 시각화 기본기

### 대시보드 도구 지형
| 분류 | 도구 | 특징 |
| --- | --- | --- |
| 기존 BI | Tableau, Power BI, Looker, Excel | 유료, 배우기 쉬움 |
| 오픈소스 | Metabase, Superset, Grafana, Lightdash | 무료, 설치·운영 부담 |
| AI 셀프 | Lovable, v0, Bolt, Claude Code | 프롬프트로 직접 제작 |

### 차트 고르기
| 보여줄 것 | 차트 |
| --- | --- |
| 추세 | 꺾은선 |
| 비교 | 막대 |
| 비율 | 도넛, 스택바 |
| 분포 | 히스토그램, 박스 |
| 관계 | 산점도 |

- **KPI**: 페이지의 한 줄 답이 되는 핵심 숫자. 모든 숫자를 키우면 강조점이 사라집니다.

### 기획서 한 줄
대시보드를 만들기 전에 독자(Who), 빈도(How often), 목적(Why)을 정합니다.

> 이 페이지는 **[독자]** 가 **[빈도]** 에 **[목적]** 을 위해 본다.

| 항목 | 예시 |
| --- | --- |
| 독자 | 병원 경영기획팀장 |
| 빈도 | 월초 경영회의 전날 |
| 목적 | 전월 진료비와 환자 구성 점검 |
| KPI | 총 명세서 수, 총 진료비, 수진자 수 |
| 차트 | 상병별 명세서 막대, 종별 건당 진료비 막대 |

### 실습
- Claude Code에 폴더를 열고 "막대 그래프 HTML 1장 만들어줘"로 그래프 생성
- 색·제목 수정은 **한 번에 한 가지씩** 요청
- Cowork로 `claim.csv` 를 주고 질의응답식으로 PRD 작성 → PRD 기반 HTML 목업 생성

## 4. 2일차: `kr_claims` 대시보드

### 데이터
| 테이블 | 행 수 | 역할 | 연결 키 |
| --- | --- | --- | --- |
| `claim` | 38,375 | 명세서 (환자·기관·날짜·주상병·진료비) | `yid`, `main_sick` |
| `institution` | 2,184 | 요양기관 종별·권역 | `yid` |
| `sick_master` | 21,299 | 상병코드 한글명 | `sickcd` |
| `code_table` | - | 종별코드 이름 | `code_type = '종별코드'` |

### 기획: AI 질의응답 3단계
1. 컬럼 목록을 주고 "누가 이 대시보드를 볼까?" → 페르소나 후보 3개
2. 페르소나 1개 선택 → 빈도·목적 정리
3. KPI 3개, 차트 2~3개 제안 받기

흔한 실수는 독자를 정하지 않는 것입니다. "낙후 지역 예산 관리" 보다 "성남시 복지정책과 사무관이 새 정책 기획에 쓰는 화면" 처럼 구체적으로 정합니다.

### 제작 단계
| 단계 | 내용 | 결과 |
| --- | --- | --- |
| Step 1 | DBeaver에서 CSV 내보내기, 폴더를 Claude Code에 전달 | `claim.csv` 등 4개 |
| Step 2 | KPI 카드 3개 | 명세서 38,375건 / 진료비 약 32.9억 원 / 수진자 2,970명 |
| Step 3 | 상병별 상위 10 막대, 종별 건당 진료비 막대 | 1위 J209 급성 기관지염 5,285건, 2위 I109 고혈압 4,403건 |
| Step 4 | 월별 꺾은선 (전체 vs 호흡기 `J%`) + 한 줄 인사이트 | 호흡기 명세서 11~3월 700~840건, 6~9월 300~380건 |
| Step 5 | GitHub push → Pages 활성화 | `github.io` 공개 URL |

종별 건당 진료비는 SQL 실습 2와 같은 쿼리로 확인했습니다. 상급종합병원 499,558원, 의원 36,019원으로 약 14배 차이입니다. 쿼리와 표는 [상위 README](../README.md#6-결과)에 있습니다.

## 5. 3일차: Supabase 연동

### 정적 vs 동적
| 구분 | 정적 (2일차) | 동적 (3일차) |
| --- | --- | --- |
| 데이터 위치 | 로컬 CSV | Supabase DB |
| 갱신 | CSV 다시 만들어 배포 | 테이블 값만 바꾸면 반영 |
| 공유 | 파일 재배포 | 여러 명이 같은 데이터 조회 |

### 순서
1. supabase.com 가입 → New project (리전 Seoul 또는 Tokyo)
2. Table Editor → Import data from CSV 로 테이블 생성
3. Project Settings > API 에서 Project URL, anon key 확인
4. Claude Code에 URL·anon key·테이블 이름을 주고 `supabase-js` 로 데이터 소스만 교체
5. 테이블 값 하나 바꾸고 새로고침해서 화면이 바뀌는지 확인

### 키 관리
- **anon key**: 화면 코드에 들어가도 되는 공개 키. 데이터 보호는 RLS 정책으로 합니다.
- **service_role key**: 관리자 키. 화면 코드나 공개 저장소에 절대 넣지 않습니다.

### 막힘 포인트
| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 데이터가 안 보임 | RLS가 기본으로 읽기를 막음 | `anon` 에 SELECT 허용 정책 추가 |
| CSV 가져오기 실패 | 컬럼명에 공백·특수문자 | 컬럼명 정리 후 다시 가져오기 |
| 키 오류 | anon key 복사 실수 | Settings > API 에서 다시 복사 |

### 클로드 스킬
- 반복 절차를 저장해 `/이름` 또는 자연어로 다시 부르는 기능
- 예: `/배포` (GitHub push + URL 안내), `/동기화` (Supabase 최신 데이터로 다시 그리기), `/주간리포트`
- 고를 때: 설치 수 1,000+, 공식 소스(anthropics, vercel-labs), 원본 저장소 stars 100+

## 7. 배운 점
- **독자부터 정한다.** 누가, 언제, 무엇을 결정하려고 보는지 정해야 KPI와 차트가 정해집니다.
- **수정은 한 번에 하나씩.** 여러 요청을 한꺼번에 하면 무엇이 바뀌었는지 확인하기 어렵습니다.
- **SQL로 숫자를 검증한다.** AI가 그린 차트의 숫자는 SQL 결과와 맞춰 봅니다.
- **공개 키와 비밀 키를 구분한다.** 공개 저장소에는 anon key만, 보호는 RLS로 합니다.
