## 2. 무엇을 배웠나

### SQL
- 조회와 조건: `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`
- 묶어서 요약하기: `GROUP BY`, `HAVING`, `COUNT(DISTINCT)`, 비율 계산
- 테이블 잇기: 명세서 + 상병마스터 + 요양기관 + 코드표 다중 `JOIN`, 분모를 지키는 `LEFT JOIN`
- 행을 남기고 옆에 붙이기: `ROW_NUMBER`, `LAG`, 누적 `SUM ... OVER`
- 단계 나누기: CTE(`WITH`)로 코호트 → 결과 → 집계
- 값을 그룹으로 묶기: `CASE` 로 병기 그룹, 0/1 플래그로 비율

### AI Agent (Claude Code)
- 대시보드 기획: 독자 → 보는 때와 이유 → KPI·차트 순서로 정하기
- 시각화 기본기: 질문에 맞는 차트 고르기, 단위와 축, 표로 보기, 라이트·다크 모드
- Agent 작업 방식: 폴더 단위로 맡기고, 한 번에 한 가지씩 요청하고, 결과를 확인한 뒤 다음 단계로
- 시스템 연동: Supabase 프로젝트와 테이블, anon key와 RLS
- 클로드 스킬: 반복 작업을 스킬로 저장하는 방법과 스킬 고르는 기준

## 4. 어떤 문제를 해결했나

| 문제 | 해결 |
| --- | --- |
| 고혈압 명세서가 0건 (`I10`) | 상병마스터에서 실제 코드 `I109` 를 확인. 0행이면 값부터 본다 |
| `ERROR 1055`, `ERROR 3593` | SQL 실행 순서를 이해하고 `GROUP BY` 보완, 윈도우 함수는 CTE에서 먼저 계산 |
| 1년 사망률이 두 배로 나옴 | `JOIN` 이 사망 기록 없는 환자를 빼서 분모가 줄었음 → `LEFT JOIN`, 단계별 행 수 확인 |
| 병기 그룹이 4개가 아니라 3개 | 문자 열을 숫자와 비교해 `'x'` 가 0이 됨 → 문자는 문자로 비교 |
| 로컬 MySQL에서 CSV 내보내기 실패 | 강의 백업 시트에서 받고 행 수·합계로 같은 데이터인지 확인 |
| 대시보드 인사이트 문장이 일부 달과 안 맞음 | 데이터와 다시 대조해 표현 수정 ("11~3월 대부분") |
| 시세 사이트에서 CSV를 받지 못함 | FRED 공개 CSV로 데이터 출처 변경 |
| 그래프 범례 등락률과 위쪽 지표가 다름 (+271.4% vs +264.2%) | 주간 데이터에 첫 거래일을 넣어 기간 시작을 맞춤 |
| "달러 쌈" 신호에 "살 때 부담" 설명이 붙음 | 상황별로 설명 문장을 나눔 |
| 다크 모드에서 차트 색이 안 바뀜 | 테마 변경 때 차트를 다시 그림 |
| Supabase 에서 0행이 읽힘, 테이블을 못 찾음(PGRST205) | CSV 가져오기 확인, 테이블 목록 새로고침, RLS 읽기(SELECT) 정책 추가 |
| 데이터는 열렸는데 브라우저에서만 "불러오는 중"에서 멈춤 | 순수 `fetch` 와 비교해 supabase-js 의 로그인 세션 확인이 원인임을 찾고, 공개 키를 `accessToken` 으로 넘겨 건너뜀 |
| 브라우저 계산이 파이썬 집계와 소수 둘째 자리에서 3곳 다름 | 파이썬 3.12 `sum()` 과 같은 보정 덧셈으로 맞춰 8개 항목 모두 일치 |

## 5. 무엇을 할 수 있게 되었나
- 청구·임상 데이터에서 현장 질문을 SQL로 바꾸고, 다중 `JOIN`·윈도우 함수·CTE로 답을 낼 수 있습니다.

- Git으로 결과물을 관리하고 GitHub Pages로 공개 URL을 만들 수 있습니다.
- 정적 대시보드를 Supabase 테이블에 연결하고, 공개 키와 RLS로 읽기 권한을 다룰 수 있습니다.
