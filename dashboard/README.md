# AI Agent 프로젝트: 건강보험 청구 데이터 웹 대시보드

## 1. 프로젝트 소개
건강보험 청구 데이터(`kr_claims`)를 보고 "어떤 상병이 많고, 종별에 따라 진료비가 얼마나 다른가"에 답하는 웹 대시보드를 만들었습니다.
코드를 직접 짜지 않고 AI Agent인 Claude Code에게 한국어로 작업을 맡겨 데이터 준비, 집계, 화면 구현, 배포까지 진행했습니다.

- 기간: 2026-10-20 ~ 10-22 (오즈코딩스쿨 AI 헬스케어 3기 웹 대시보드 특강, 3일), 과제 마무리 10-28
- 데이터: `kr_claims` 명세서 38,375건(2024-01 ~ 2025-12), 요양기관 2,184곳, 상병마스터 21,299건, 수진자 정보 / 과제 1은 S&P 500 일별 종가(FRED)
- **대시보드**: https://jihyeongh21-svg.github.io/nano-degree-sql-ai-agent/dashboard/
- **과제 1 그래프 (S&P 500)**: https://jihyeongh21-svg.github.io/nano-degree-sql-ai-agent/dashboard/sp500.html

> 데이터는 실제 환자 기록이 아닌 실습용 가상 데이터입니다. 숫자를 실제 통계로 해석하지 않습니다.

## 2. 제작 목적
- **비싼 BI 없이 대시보드 만들기**: Tableau 같은 BI는 라이선스 부담이 크고, Metabase 같은 오픈소스는 설치·운영 부담이 있습니다. AI Agent로 비개발자도 직접 만들 수 있는지 확인했습니다.
- **분석 질문에 바로 답하는 화면**: SQL로 매번 쿼리를 돌리지 않고, 독자가 화면을 열자마자 핵심 숫자를 보게 합니다.
- **재현 가능한 결과물**: 집계 스크립트와 프롬프트를 남겨, 데이터가 바뀌어도 같은 절차로 다시 만들 수 있게 합니다.

## 3. 사용 기술
- **Claude**: Claude Code
- **AI Agent 관련 기술**
  - 폴더 단위 작업: Agent가 폴더 안 파일을 직접 읽고 만들고 고침
  - 질의응답식 기획: Agent와 대화로 페르소나·KPI·차트를 정함
  - 단계별 프롬프트: 한 번에 한 가지씩 요청 ([`PROMPTS.md`](PROMPTS.md))
- **기타 기술**
  - Python 표준 라이브러리 (CSV 집계)
  - HTML + Chart.js 4.4.1
  - GitHub Pages (배포)
  - MySQL 8.4 + DBeaver (SQL 수업에서 숫자 검증)

## 4. Agent 구조

```
[사용자] 한국어 요청 (PROMPTS.md)
   │
   ▼
[Claude Code]
   ├─ 데이터 받기 ──▶ kr_claims 백업 시트 → scripts/.cache/*.csv
   ├─ 집계 ────────▶ scripts/build_data.py → data.js
   ├─ 화면 생성 ───▶ index.html (대시보드), sp500.html (과제 1), age-cost.html (실습)
   ├─ 검증 ────────▶ SQL 결과와 숫자 대조, Edge headless 스크린샷
   └─ 배포 ────────▶ git push → GitHub Pages 공개 URL
```

1. **기획**: Agent와 3단계 질의응답(누가 보나 → 언제·왜 보나 → 어떤 KPI·차트)으로 기획서를 만듭니다.
2. **집계**: Agent가 CSV를 읽어 KPI·상병·종별·월별·연령대 집계를 `data.js` 하나로 만듭니다.
3. **구현**: Agent가 `data.js` 를 읽는 HTML을 만듭니다. 수정은 한 번에 한 가지씩 요청합니다.
4. **검증·배포**: 숫자를 SQL 결과와 맞춰 보고, 화면을 스크린샷으로 확인한 뒤 GitHub Pages로 배포합니다.

## 5. 주요 기능
- **KPI 카드 3개**: 총 명세서 수, 총 진료비, 수진자 수 (건당 평균, 1명당 명세서 수 보조 표시)
- **주상병별 명세서 상위 10**: 가로 막대, 상병마스터 한글명
- **종별 건당 평균 진료비**: 세로 막대, 툴팁에 명세서 수와 본인부담률
- **월별 꺾은선**: 전체 vs 호흡기 질환(`J%`) 명세서
- **한 줄 인사이트**: 숫자 근거와 함께 대시보드 하단에 표시
- **과제 1 그래프**: S&P 500 10년 주간 종가 꺾은선, 1·3·5·10년 기간 선택, 최대 낙폭·연도별 수익률
- **실습 그래프**: 연령대·성별 환자 1명당 2년 진료비
- **접근성**: 차트마다 "표로 보기", 라이트·다크 모드, 모바일 한 열 배치

## 6. 내가 수행한 내용
- **기획서 작성**: 이 페이지는 **병원 경영기획팀장** 이 **월초 경영회의 전날** 에 **전월 진료비와 환자 구성을 점검** 하기 위해 봅니다.

  | 항목 | 내용 |
  | --- | --- |
  | 독자 | 병원 경영기획팀장 |
  | 빈도 | 월초 경영회의 전날 |
  | 목적 | 전월 진료비와 환자 구성 점검 |
  | KPI | 총 명세서 수, 총 진료비, 수진자 수 |
  | 차트 | 상병별 명세서 막대, 종별 건당 진료비 막대, 월별 꺾은선 |

- **과제 1 주제 선정**: "S&P 500은 10년 동안 어떻게 움직였나"를 과제 1 주제로 정함
- **실습 주제**: "나이가 들수록 진료비는 얼마나 늘어날까"를 청구 데이터로 실습
- **Agent 작업 지시**: 데이터 준비 → 집계 → KPI → 차트 → 인사이트 → 배포 순서로 단계별 요청
- **숫자 검증**: Agent가 낸 숫자를 SQL 수업 결과와 대조 (7절)
- **인사이트 문장 수정**: 데이터 범위를 벗어나는 달을 확인하고 표현을 고침
- **배포**: GitHub Pages로 공개 URL 확보

### 막힌 점과 개선
| 문제 | 원인 | 개선 |
| --- | --- | --- |
| 로컬 MySQL에서 CSV를 내보내지 못함 | WSL에서 root 비밀번호 없이 접속 거부 (`ERROR 1045`) | 강의 백업 구글 시트에서 같은 데이터를 CSV로 받고, 행 수·합계로 동일한지 확인 |
| 인사이트 "11~3월 700~840건"이 일부 달과 안 맞음 | 2024년 1월 호흡기 명세서는 532건 (데이터 시작 달) | "11~3월 대부분" 으로 표현 수정 |
| 그래프 주석 "70세 이상은 환자 수가 적다" 가 사실과 다름 | 70세 이상도 남 146명, 여 217명 | "남성은 70세 이상에서 오히려 줄어든다" 로 수정 |
| y축 0 눈금이 "0만" 으로 표시 | 단위 변환 함수가 0에도 "만"을 붙임 | 0은 "0" 으로 표시 |
| 종별 이름에 다른 코드가 섞일 위험 | `code_table` 에 여러 코드 종류가 있음 | `code_type = '종별코드'` 행만 사용 |
| 다크 모드에서 차트 색이 안 바뀜 | Chart.js 색은 그릴 때 한 번 정해짐 | 테마 변경 이벤트에서 차트를 다시 그림 |

## 9. 배운 점
- **독자부터 정한다.** 누가, 언제, 무엇을 결정하려고 보는지 정해야 KPI와 차트가 정해집니다.
- **Agent에게는 작게 나눠 시킨다.** 한 번에 한 가지씩 요청해야 결과를 확인하고 되돌리기 쉽습니다.
- **Agent가 만든 숫자와 문장은 검증한다.** 차트가 그려졌다고 숫자가 맞는 것은 아닙니다. 인사이트 문장도 데이터와 한 번 더 대조해야 했습니다.
- **막히면 같은 데이터를 다른 경로로 받는다.** DB 접속이 막혀도 백업 데이터로 진행하되, 행 수와 합계로 같은 데이터인지 확인합니다.
- **재현성을 남긴다.** 집계 스크립트와 프롬프트를 남기면 데이터가 바뀌어도 같은 결과를 다시 만들 수 있습니다.
